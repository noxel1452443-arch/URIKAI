## 0. 確定した方針

| 項目 | 決定 |
|------|------|
| 名称 | **カイのすみか** |
| 待ち | **進捗のみ**（日数ロックなし）。ただし1日（想定 3〜10 プレイ）では大きく進めない密度 |
| 見た目 | **5 グレード**（イラストが変わる単位） |
| 強化 | グレード内に **多数レベル**（気軽に上げられる）。境界レベルでグレードアップ |
| 操作分離 | **整える＝シート内**／**受け取る＝ホームの金額ポップ**（二重ボタンにしない） |
| 割り込み | 受取のためのバナー・カイ一言強制は **しない** |
| インカム | **2経路**（プレイごと ＋ 時間経過）。未受取ポケット＋キャップ |
| 購入ガード | **しない**（使いすぎて元手が小さくなるのもプレイ味） |
| 破産 | **撤廃**（立て直しブーストもなし。§7） |
| レリック閾値 | g 加速に合わせ **外側へ再配置**（§8・簡易モデル） |

## 2. 「お給料」の呼び方と世界観

### 懸念
「カイのお金を奪っている」感。ロボアド雇用説は、すみかを用意する側と矛盾し、かつ **ゲーム内で世界観を説明する導線が弱い**。

### 推奨
**重い設定は書かない。** 呼び方は **お給料** の響きを残し、関係性だけソフトにする。

- 同じ画面・同じ部屋にいる同居感（カイはマスコット住人、プレイヤーは口座を動かす人）
- お給料＝「カイがすみかにいるあいだ、口座へ回してくれる生活のお金」  
  （奪う／雇う、ではなく **共同の財布に入る**）
- UI 文言例: 「カイのお給料」「すみかの入り」サブで補足してもよいが、主語はお給料でよい
- どうしても気になる場合の別名候補: 「おこづかい」「入り」「まもり代」— ただし響きはお給料が勝つ

世界観の長文はノート1項目で後付け可能。起動時に説明しない。

## 3. レベル × 見た目グレード

### 3.1 構造

```
Lv 0          … すみかなし（床だけ）
Lv 1〜9       … 見た目「わらのす」（鳥の巣風）
Lv 10         … グレードアップ → 「ふかふかざぶとん」
Lv 10〜24     … ふかふかざぶとん（クッションねぐら）
Lv 25         … → 「ちいさなドーム」（入れるペットドーム）
Lv 25〜44     … ちいさなドーム（外観＋内装ビュー）
Lv 45         … → 「みみや」（耳をひさしにした小屋）
Lv 45〜69     … みみや
Lv 70         … → 「ヘッドセットハウス」（通信本拠・最上）
Lv 70〜99     … ヘッドセットハウス
```


- **表示**: `Lv.12` ＋ グレード名「あさのマット」  
- **特殊強化**（グレード境界）: 費用・必要進捗を一段大きく、演出を厚く  
- 通常レベルアップ: 安め・頻繁（「気軽にたくさん」）

レベル上限・境界値は調整用定数にする（上表は叩き台）。

### 3.2 グレード解放（出金回数ゲートは使わない）

出金回数による進捗ゲートは**廃止**。代わりに見た目グレードを報酬で解放する。

1. **最初はなし** — ホームにすみかを出さない（Lv0）  
2. **最高残高 ≥ ¥12,000** で「草のしき布」を報酬受け取り → Lv1。シートで **Lv9まで**強化可。Lv9では次Lvを見せない（いまが最大に見える）  
3. **Lv9の状態で1プレイ（出金）クリア**すると「あさのマット」を報酬受け取り可能。受け取り後、Lv9シートに **グレードアップボタン**（→Lv10）が出る  
4. 以降同様: キャップ（24 / 44 / 69）到達 → 出金1回 → 次グレード報酬 → グレードアップ → 次帯の強化  

やらないこと: 「あと1プレイで解放」ヒント、押せない次レベルボタン、出金あと○回表示。

## 4. 操作とUI（二重ボタンにしない）

### 4.1 ホーム上のすみか

```
        [ +¥640 ]     ← 未受取 > 0 のときだけ。すみかの外側にポップ
           │
      ┌────┴────┐
      │  すみか  │     ← タップ①: ポップをタップ → 受取演出のみ
      │ (イラスト)│     ← タップ②: 本体をタップ → 詳細シート（整え）
      └─────────┘
```

- **金額ポップをタップ** → 受取（放置系の一瞬演出）→ 口座残高がカウントアップ  
- **すみか本体をタップ** → 詳細シート（フレーバー・大イラスト・効果・レベルアップ）  
- ポップがないとき、本体タップはシートのみ  
- カイ本体タップは従来どおりセリフ。給料受取とは混ぜない  
- **出金後のバナー／強制一言は使わない**（テンポ優先）

### 4.2 詳細シート（整える専用の顔）

- ホーム上に「すみか」ラベルは出さない（イラストのみ）  
- ボトムシート: タイトル・大イラスト・グレード名＋`Lv.n`・フレーバー  
- 効果は **2つの数字セル**（お給料/プレイ・お給料/6ふん）。長文説明はしない  
- 主操作は一つ: **レベルアップ ¥…**（反転ボタン）  
  - 残高不足のときだけ「残高が足りない」。進捗ゲートは内部のみ（回数テキストは出さない）  
- 次のグレード境界が近いときだけ「次の見た目」プレビュー

## 5. インカム 2 経路

未受取ポケット `pendingYen`。口座へは **受取タップ時のみ**。

### 5.1 プレイごと（主）

出金確定のたび:

```
pendingYen += payPerPlay(level)
pendingYen = min(pendingYen, cap)
```

- Lv1 帯の目安: **payPerPlay ≈ ¥300**（以前の数十円はプレイフィール不足）  
- レベルで緩やかに上昇（グレード境界で一段上がる）

### 5.2 時間経過（副）

- 間隔: **6 分**に 1 回  
- 量: **payPerPlay / 10**（Lv1 なら ¥30）  
- アプリが裏にいても、次回フォアグラウンドで経過刻みをまとめて加算（運用日次と同様）

### 5.3 キャップ

```
cap = payPerPlay * 3
```

Lv1 なら未受取上限 ¥900。取り逃しすぎを防ぎつつ、放置の無限増殖を止める。

### 5.4 受取演出

1. ポップが吸い込まれて消える（短く）  
2. ホームの口座残高表示が **カウントアップ**（メインのフィードバック）  
3. SE 短く  
4. 明細に「カイのお給料」1行  

シートを開かせない。プレイテンポを切らない。

## 6. 給料テーブル（叩き台）

`payPerPlay` をレベル関数にする。例:

| Lv | グレード | payPerPlay | 6分ごと | cap |
|----|----------|------------|---------|-----|
| 1 | 草 | 300 | 30 | 900 |
| 9 | 草 | 420 | 42 | 1260 |
| 10 | あさ | 480 | 48 | 1440 |
| 25 | き | 700 | 70 | 2100 |
| 45 | ふとん | 1000 | 100 | 3000 |
| 70 | うもう | 1400 | 140 | 4200 |

**1日あたりのざっくり g（受取を怠らない場合）:**

- プレイ分: `payPerPlay × プレイ回数`（6回×300 = 1,800）  
- 時間分: キャップに当たるまで。起きてるあいだこまめに取るとプレイ分と同オーダーになり得る  

→ g は無視できない加速装置。だから §7・§8 が必須。

### 6.1 レベル費用・進捗（確定叩き台）

**グレード境界 Lv:** 10 / 25 / 45 / 70（見た目変化）。上限 Lv99。

**`payPerPlay(lv)`（円）** — 境界で一段上がり、間は線形補間:

| Lv | payPerPlay | 6分 | cap×3 |
|----|------------|-----|-------|
| 1 | 300 | 30 | 900 |
| 9 | 420 | 42 | 1260 |
| 10 | 480 | 48 | 1440 |
| 24 | 650 | 65 | 1950 |
| 25 | 700 | 70 | 2100 |
| 44 | 900 | 90 | 2700 |
| 45 | 1000 | 100 | 3000 |
| 69 | 1250 | 125 | 3750 |
| 70 | 1400 | 140 | 4200 |
| 99 | 1800 | 180 | 5400 |

**`cost(lv)`** — Lv に上げる費用:

- Lv1: ¥600  
- 通常: `floor(350 × 1.055^(lv-2))`  
- 境界: Lv10=¥3,500 / 25=¥8,000 / 45=¥16,000 / 70=¥32,000  

**累計出金ゲート `minCashouts(lv)`:**

- Lv1: 2  
- 以降: 通常 `+ (2 + lv//15)`、境界レベルは `+12`  
- 目安: Lv10≈28 出金、Lv25≈70、Lv45≈140、Lv70≈240（1日6プレイなら数日〜週〜月）

## 7. 購入ガードなし／破産撤廃

### 7.1 購入ガードはしない

使いすぎて残高が数百円になり、**次プレイの元手が小さい → r が小さくなる**一方、g（お給料）は残る、という状態はあり得る。

これはバグではなく味になりうる（「生活費に使いすぎた日」）。  
ガードで叱るより、**自分で配分を学ぶ**方が r と g の両輪に合う。

制約は最小だけ:

- レベルアップは `balance >= cost` のときだけ（足りなければ不可）  
- **破産ラインを意識した追加ガードは置かない**

### 7.2 破産システムは撤廃

| やめる | 理由 |
|--------|------|
| 残高 < ¥5,000 で強制リセット | すみか支出・連敗と救済が一括大金で不自然 |
| 「低残高でお給料×2」 | 意図的に低残高を維持して倍増を使う逆インセンティブ |

株で負けても、すみかに使いすぎても、**お給料と運用と再プレイで立て直す**。それがこのゲームの回復手段。

### 7.3 低残高の救済（カイのお小遣い）

破産リセット／¥10,000 出直しは置かない。代わりに:

- `balance == 0` の間はプレイ開始不可  
- **`balance < ¥100`** のとき、カイの上にすみか給料と同じ **+¥100 ポップ**が出る  
- タップで受取 → 口座カウントアップ（給料と同じ演出）＋カイの一言  
  （「かわいそうだから、お小遣い分けてあげるよ…」系）  
- **1 回もらうと、次の 1 プレイ（出金）まで再受取不可**  
- 例外: `balance == 0` のときは詰み回避のためブロックを無視して再受取可  
- すみか Lv≥1 なら時間経過で pending も貯まる → 受け取って再開できる  

立て直しブースト・破産オーバーレイは実装から外す。
