# 収益化・広告（学習目的・最小構成）

> 目的は黒字化ではなく、**初回作で「公開 → 広告/課金 → 計測」を経験すること**。  
> コア（60秒・1ボタン・ラグ読み）は壊さない。

## 確定方針

| 項目 | 決定 |
|------|------|
| 配信 | Google Play 公式 |
| 広告 | AdMob インタースティシャル（リザルト→ホーム前）。**ゲーム内の寝床・カイ生活が整うまで後回し** |
| 課金 | **広告除去・買い切り IAP** `urikai_remove_ads`（Billing 接続済み・購入テストは継続可） |
| 計測 | Firebase 等は段階導入（広告接続と同タイミングでよい） |
| プレイ中広告 | **出さない** |

## 頻度・ガード

### 強制インタースティシャル（1系統）

| いつ | 条件 |
|------|------|
| リザルト確定 → ホームへ戻る直前 | `adsRemoved == false` かつ出金カウンタが 3, 6, 9… |

- 起動直後ホーム・プレイ中には出さない。未準備／失敗／除去済み → すぐホーム

### 任意リワード（2系統・実装済み）

| 系統 | UI | 効果 | 日次上限 |
|------|-----|------|----------|
| 給料2倍 | お給料ポップ下のリンク | 未受取ポケット×2（受取まで再適用不可） | 3回 |
| レベルアップ半額 | すみかシートのアップグレード下 | 表示費用÷2（積み重ね可・最低¥1） | 3回 |

- `adsRemoved == false` → リワード視聴後に付与
- `adsRemoved == true` → **視聴スキップで同効果**（文言は「2倍にする」「半額にする」）
- 本番ユニット: `local.properties` の `admob.rewarded.id`（未設定時は公式テスト ID）
- **起動最適化**: `MobileAds.initialize` と広告プリロードは初回 Compose 描画の約 1.5s 後。インタースティシャル→8s 後にリワードの順（同時ロードによる初回遅延・エミュ OOM を避ける）

## カイの寝床＝インカム(g)レーン

運用方針の日次変動は **r（資産運用）**。チャート60秒は **デイトレ的な r**。  
寝床はそれとは別の **固定給与 g**。

| ルール | 内容 |
|--------|------|
| 家具種 | **寝床1種のみ**（草→麻→木→布団→羽毛） |
| 収入 | 出金1回ごとに固定額（ランク依存） |
| 費用 | 口座¥（段階的に高額） |
| 解禁 | **出金回数＋最高残高**の進捗ゲート（壁時計の分／時間待ちは使わない） |
| The Tower 型 | 購入→待ち→完了の研究所ループは **見送り**（短時間なら序盤で消化、長時間なら日数級＋多段レベルが必要で核と合わない） |
| 広告 | 時間短縮前提は撤回。割引などの別案を後で検討 |
| 破産 | 寝床は消えない |

現行ゲート（調整可）:

| ランク | 費用 | 給与/出金 | 目安：出金 | 目安：最高残高 |
|--------|------|-----------|------------|----------------|
| 草 | ¥800 | +¥50 | 1 | ¥10,000 |
| 麻 | ¥2,000 | +¥90 | 8 | ¥12,000 |
| 木 | ¥4,500 | +¥150 | 18 | ¥16,000 |
| 布団 | ¥9,000 | +¥240 | 40 | ¥24,000 |
| 羽毛 | ¥20,000 | +¥360 | 70 | ¥40,000 |

イラスト手順: `docs/kai-concepts/BED_SPRITE_SPEC.txt`（カイ本体と同系。未解放プレビューも手を抜かない）

## 正しい順番（ここを守る）

Play Console は **BILLING 権限付き APK/AAB がどれかのトラックに無いと、商品作成 UI が出ない**。  
「新しい APK をアップロード」しか出ないのは正常。**先に AAB を上げてから商品を作る。**

1. （コード側）Billing Library + `BILLING` 権限入り AAB を作る ✅
2. クローズド／内部テストにその AAB をアップロードして配信 ✅（想定）
3. **1回限りの課金アイテム** `urikai_remove_ads` / 購入オプション `buy` / ¥290 有効化 ✅
4. **ライセンステスターで実機購入テスト** ← いまここ

### 購入テスト手順（いまやること）

1. Play Console → **設定 → ライセンス テスト** に、端末の Google アカウントを追加して保存  
2. 最新 AAB（versionCode **7** / 1.7.4）をクローズド（または内部）へ上げて配信  
3. テスターアカウントで Play からその版をインストール（USB の古い debug では課金シートが出ないことが多い）  
4. アプリ → 設定 → **なしにする（REMOVE）** → Play 購入シート  
5. 成功すると ADS が **OWNED** 表示。金額はテスターなら課金されない  

失敗時の確認: Logcat で `UriKaiBilling`。商品未有効・offerToken 無し・別アカウントだと失敗しやすい。

## FAQ（クローズドテストと ID）

### 課金商品 ID はクローズド中に作れる？

**作れる。** Play Console の「収益化 → アプリ内商品」は、内部／クローズドにビルドがある段階でも作成・有効化できる想定。  
Billing Library を入れた APK/AAB をいずれかのテストトラックに上げ、ライセンステスターで購入テストするのが定石。  
「クローズドだからメニューが出ない」場合は、支払いプロフィール未完了や Console の収益化セットアップ途中が多い。

### AdMob はクローズドだとアプリ登録できない？

**ストア検索連携はできないが、未公開アプリとして登録はできる。**  
クローズド／内部テストのパッケージは「公開ストアのアプリ」としてリンクできない。  
→ AdMob で「いいえ、未公開」→ package name 手入力 → **アプリ ID と広告ユニット ID は今すぐ取れる**。  
本番公開後に Play と連携し、審査（app readiness）を通す。

### クローズド登録時は「広告なし」だった。いつ変える？

| タイミング | 推奨 |
|------------|------|
| いま（広告 SDK 未接続） | ストア宣言は実態どおり「広告なし」のままでも可。ポリシー URL は広告予定を書いておく（上記更新済み） |
| M2 で SDK 接続・広告付き AAB を上げる直前〜同時 | Play の「広告あり」／データセーフティ／広告 ID 宣言を **実態に合わせて更新** |
| 審査申請（本番申請）前 | 必ず広告あり前提で揃える。クローズド中に先に変えてもよい |

**審査の前後どちらでも Concsole 上は変更可能。** 重要なのは「公開中のビルドの挙動」と「ストア宣言・ポリシー」が一致していること。  
クローズド中に広告付きビルドを配るなら、その時点で宣言を合わせる。広告なしビルドのままなら宣言は後でもよい。

### クローズド公開されていれば ID は取れる？

- **Play 商品 ID**: クローズドで十分（収益化セットアップさえ通れば）
- **AdMob アプリ／ユニット ID**: 未公開登録で取れる。Play のクローズド公開は必須ではない
- **AdMob のストアリンク**: 本番（一般公開）後
